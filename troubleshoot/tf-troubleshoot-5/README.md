# 🚨 SRE Incident Lab: tf-troubleshoot-5 — NexusVault Stateful Platform (State Disasters, Refactoring & Ansible Precedence Outage)

Welcome to **tf-troubleshoot-5**. This workspace simulates a high-severity production outage on **NexusVault**, a stateful secret management node where an interrupted CI job and a code refactor broke the **Terraform State**, while the **Ansible** role hierarchy suffers from a variable precedence trap and a conditional type bug that leaves the Vault service sealed (`HTTP 503`).

Your mission as the Lead On-Call SRE is to resolve the incident tickets **in strictly sequential order** from **INC-501** to **INC-505** without losing the original production `vault_cluster_id`.

## 🔍 Incident Triage & Verification Playbook

---

### [INC-501] Lost Terraform State Recovery

* **Observed Symptoms:**
  * `terraform.tfstate` is missing in `terraform/`.
  * If you run `terraform apply` without restoring the state, Terraform generates a brand-new `vault_cluster_id`, which fails the production integrity check in `/tmp/nexusvault-lab5/etc/nexusvault/expected_cluster_id.txt`.
* **Triage Commands (Before Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/terraform
  ls -la terraform.tfstate*
  cat /tmp/nexusvault-lab5/etc/nexusvault/expected_cluster_id.txt
  terraform plan || true
  ```
* **Verification Commands (After Fix):**
  ```bash
  # Restore terraform.tfstate from terraform.tfstate.backup
  ls -l terraform.tfstate
  ```

---

### [INC-502] Refactoring Protected Resource Without Destruction (`moved` / `state mv`)

* **Observed Symptoms:**
  * Once `terraform.tfstate` is restored from backup, running `terraform plan` fails with:
    `Error: Instance cannot be destroyed — Resource random_id.cluster_id has lifecycle.prevent_destroy set`.
  * A developer renamed `random_id.cluster_id` to `random_id.vault_cluster_id` in `main.tf` without migrating its state address.
* **Triage Commands (Before Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/terraform
  terraform state list
  terraform plan
  ```
* **Verification Commands (After Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/terraform
  terraform plan
  # Expected: No changes (or 0 to destroy) and vault_cluster_id matches expected_cluster_id.txt!
  ```

---

### [INC-503] Targeted Secret Rotation (`-replace`)

* **Observed Symptoms:**
  * The SHA-256 hash of `random_password.api_token` matches the leaked hash in `/tmp/nexusvault-lab5/etc/nexusvault/leaked_token_sha256.txt`.
  * You must rotate `random_password.api_token` and update `hosts.ini` / `bootstrap.json` while keeping `vault_cluster_id` untouched.
* **Triage Commands (Before Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/terraform
  terraform output -raw api_token_sha256 && echo ""
  cat /tmp/nexusvault-lab5/etc/nexusvault/leaked_token_sha256.txt
  ```
* **Verification Commands (After Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/terraform
  # Compare new token hash against leaked hash (must be different!) while cluster_id remains identical:
  test "$(terraform output -raw api_token_sha256)" != "$(cat /tmp/nexusvault-lab5/etc/nexusvault/leaked_token_sha256.txt)" && echo "TOKEN ROTATED SUCCESSFULLY"
  test "$(terraform output -raw vault_cluster_id)" = "$(cat /tmp/nexusvault-lab5/etc/nexusvault/expected_cluster_id.txt)" && echo "CLUSTER ID PRESERVED"
  ```

---

### [INC-504] Ansible Role Variable Precedence Trap (`vars/` vs `group_vars/` vs `defaults/`)

* **Observed Symptoms:**
  * Running `ansible-playbook site.yml` succeeds, but `curl http://127.0.0.1:18200/v1/sys/health` fails with `Connection refused`.
  * Inspecting `/tmp/nexusvault-lab5/etc/nexusvault/vault-config.json` reveals `"listen_port": 19999` instead of `18200`, even though `group_vars/all.yml` defines `vault_listen_port: 18200`.
* **Triage Commands (Before Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/ansible
  ansible-playbook site.yml
  cat /tmp/nexusvault-lab5/etc/nexusvault/vault-config.json
  grep -rn "vault_listen_port" .
  ```
* **Verification Commands (After Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/ansible
  ansible-playbook site.yml
  grep '"listen_port": 18200' /tmp/nexusvault-lab5/etc/nexusvault/vault-config.json
  ```

---

### [INC-505] Ansible `when:` String-vs-Integer Type Evaluation Trap

* **Observed Symptoms:**
  * NexusVault is now listening on port `18200`, but `curl -i http://127.0.0.1:18200/v1/sys/health` returns `HTTP/1.0 503 Service Unavailable` with `"sealed": true`.
  * During `ansible-playbook site.yml`, the task `Unseal NexusVault when seal threshold equals 2` shows `skipping: [nexusvault-01]` even though `hosts.ini` sets `vault_seal_threshold=2`.
* **Triage Commands (Before Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/ansible
  curl -i http://127.0.0.1:18200/v1/sys/health || true
  cat hosts.ini
  cat roles/vault-agent/tasks/main.yml
  ```
* **Verification Commands (After Fix):**
  ```bash
  cd /home/ysf/k8sfundamentals/Troubleshoot/tf-troubleshoot-5/ansible
  ansible-playbook site.yml
  curl -s http://127.0.0.1:18200/v1/sys/health

  ```
